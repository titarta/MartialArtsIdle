The pattern-click mini-game today looks like an osu! ripoff: numbered purple discs on a flat black scrim, with a generic purple→blue gradient timer bar. There is no thematic anchor for what the player is doing. The mechanic is called Tracing Meridians — the player is supposed to be channelling qi through acupressure points along the body's meridian channels. That fantasy is invisible today.

This pass replaces the dots with acupressure node medallions (lacquer-and-brass, with Chinese numerals inside), the timer with a burning-incense bar (dark column with a glowing tip that recedes), and the SVG lines with calligraphic ink-meridian strokes that the active segment lights up in brass. Also fixes the dot-placement bug so the nodes never spawn behind permanent UI.

The placement bug

generateDotPositions() rolls coords as x = 8 + Math.random() * 80 and y = 14 + Math.random() * 65. Those percentages map to the overlay's box, not the viewport. The overlay is already top: var(--top-bar-h); bottom: var(--nav-h) — so the 14% y-margin and 65% y-range are doing double duty beyond what the overlay already excludes.

Worse: the safe-zone math ignores the in-scene UI that lives inside the overlay's bounds: top-left chip stack (~20% × 30% top-left), Petition Tablet (~20% × 32% top-right), crystal + cultivator (~40% × 50% centre-bottom), and the BT button when pending (~80% × 18% bottom centre). The dots roll uniformly across that whole rectangle — so on most rolls, at least one dot lands underneath a chip, the tablet, or the cultivator. Tapping the cultivator passes the tap to the dot, but tapping the tablet (or chip) opens that UI instead of the dot.

At T5 (7 dots) with MIN_DIST = 20%, the 400-attempt loop times out routinely on tall phones, and the fallback grid kicks in — dots clump on a diagonal staircase.

The fix

  • Reuse the existing safe-zone discipline. The Sanctum layout already uses SPARK_SAFE_ZONES (two side-channel bands flanking the cultivator) for divine_qi orbs and the prompt itself — use the SAME bands for dot generation.
  • Constrain dot positions to the safe channels. Each dot rolls a zone (alternating L/R for spatial flow), then random within the zone. No collision with chips, tablet, cultivator, BT button.
  • Drop the redundant top-margin. The overlay already excludes the top bar; the title strip + incense timer take ~60px from the top of the overlay box — encode that as a 14% offset of the OVERLAY (not viewport) and call it once.
  • Lower MIN_DIST adaptive. Scale by dotCount: 3 dots can afford 22%, 7 dots needs ~14% to avoid fallback. Add jitter on retry.
  • Anchor SVG paths to the same coord system as the dots. Use viewBox="0 0 100 100" preserveAspectRatio="none" on the ink SVG so % paths and % dots use the identical projection.
Implementation order: (1) fix dot placement bug — single-PR — small + risk-free; (2) ship the redesigned overlay + nodes + incense timer; (3) ship the ink-stroke connections + traveler orb. CSS-only motion throughout — no React state thrash for the spin, stamp, or burn animations.
